Техническое задание на проект: Travel Budget
1. Название и концепция
Название: Travel Budget
Концепция: Веб-сервис для планирования бюджета и трекинга расходов во время путешествий. Проблема, которую решает приложение — сложность учета финансов в поездках, особенно когда траты происходят в разных валютах. Сервис позволяет пользователю видеть, сколько денег осталось от бюджета в пересчете на рубли, и анализировать траты по категориям.

4. Схема данных (Сущности)
Модель 1: Trip (Путешествие)
Основная сущность, группирующая расходы.
Поля:
user (ForeignKey -> User): Владелец записи.
name (CharField): Название (например, "Тайланд 2024").
budget (DecimalField): Планируемый бюджет в рублях.
start_date (DateField): Дата начала.
end_date (DateField): Дата окончания (необязательно).
Модель 2: Expense (Расход)
Запись о конкретной трате.
Поля:
trip (ForeignKey -> Trip): Ссылка на путешествие (ON_DELETE=CASCADE).
title (CharField): Описание траты.
amount (DecimalField): Сумма в оригинальной валюте.
currency (ForeignKey -> Currency): Валюта траты.
category (CharField + Choices): Категория (Еда, Транспорт, Жилье, Развлечения, Шоппинг, Прочее).
date (DateField): Дата совершения траты.
Логика: Свойство amount_in_rub для динамической конвертации.
Модель 3: Currency (Валюта)
Справочник валют.
Поля:
code (CharField): ISO код (USD, EUR, THB).
name (CharField): Название.
rate_to_rub (DecimalField): Текущий курс к рублю.
5. Основные сценарии (User Stories)
Планирование: Пользователь создает поездку "Отпуск в Сочи", устанавливает бюджет 100 000 руб.
Учет расходов: Пользователь добавляет трату "Обед" на сумму 1500 руб. (категория "Еда"). Затем добавляет "Сувениры" на 50 USD (категория "Шоппинг"). Система конвертирует 50 USD в рубли и обновляет остаток бюджета.
Аналитика: Пользователь заходит на страницу поездки и видит:
Круговую диаграмму (Pie Chart): На что ушло больше всего денег.
График по дням (Bar Chart): В какие дни были пиковые траты.
Метрики: "Потрачено: 45 000 ₽", "Осталось: 55 000 ₽".
